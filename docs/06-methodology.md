# 06 · 测量协议与判据写法（跨线通用）

> 这套协议是**用若干次整跑的代价换来的**。复用本仓库的结论时，请连协议一起带走——
> 否则很可能复现出一个"看起来支持、其实什么都不支持"的数字。

---

## 1. 三把尺，判决时必须写明用哪把

| # | 尺 | 定义 | 适用 |
|---|---|---|---|
| ① | **交付口径（max-of-N）** | 训练全程若干次评测的**最大值** | 版本间比较（可跨跑） |
| ② | **平台口径** | 基线 ± 2σ | 判断"是否超出噪声" |
| ③ | **同权重配对** | 同一份权重下两个读数的逐样本配对差 | **机制判据的黄金标准** |

**噪声底**（实测，两次独立训练之间）：
- B 线 CIFAR-10：`σ_diff = 0.169pp`
- A 线 CIFAR-100：`σ_seed = 0.71pp`

⇒ 判据里的 PASS 线 = 基线 + 2σ；红线 = 基线 − 2σ（B 线：基线 97.50 / PASS 97.838 / 红线 97.04）。

---

## 2. 交付判据（J0）与机制判据（J1）必须成对

- **J0**：可跨跑比（就是精度 / 回报）。
- **J1**：**必须同跑内配对**。它回答"干预有没有送到"，J0 回答"送到之后有没有用"。

**为什么强制成对**：max-of-N 的新峰值可能只是**抽签**。
B 线 v43 的 delivered 97.41 = 平台均值 +1.41 个平台 sd ⇒ 峰值不是真峰值。
只有 J1 配对才能把"抽签"与"真信号"分开。

**硬失败条件只允许"守卫不成立"**：

> 若 J1 的守卫（干预是否送达）不成立，NULL 只能读成「干预没送到」，
> **不许读成"机制无效"**。

---

## 3. 判据写法的具体纪律

| 纪律 | 说明 | 反面例子 |
|---|---|---|
| **逐位一致打在 logits 上** | 必须验 `max\|Δlogit\| == 0`，不能只比 acc | `abs(ref_acc − mcnemar(lg_ref, lg_ref))` 恒真 |
| **配对方法本身要被配对校验** | 把逐样本 logits 存下来，可从存档重算 n01/n10 验算 JSON | 只存聚合数 |
| **守卫的覆盖域要先审** | 只校行数不校行序 + loader 固定 `shuffle=False` ⇒ 设计上不可能失败 ⇒ PASS 不是证据 | v41 的 `rows_ok` |
| **频率标尺要对齐** | B 线曾发现 DFT 频率标尺错一档（`endpoint` 问题，自 v9 起）⇒ 修标尺是**仪器**改动，不是轴 | — |
| **读数时点 ≠ 同一观测量** | `best_tta_acc`（179 次评测的 max）系统性高于任何一次末态重测 | 拿两者相减当噪声 |
| **单点终点不可用于版本对比** | Breakout 相邻 20K 采样可差 ±50% | v8 被 5M 单点误判 |

## 4. 判词必须"内容优先"定序

以 `v119` 的判词为例（可直接复用这个结构）：

```
1. 空转闸门（先排除"根本没跑到"）：
     hp_frac < 0.02                      -> TARGET_EMPTY
     grad_max_hp <= 0                    -> GRAD_DEAD
     探针本身崩了                        -> READOUT_ERROR
2. 唯一成败判据（内容）：
     band_frac >= 0.20                   -> DELIVERED
3. 失败细分（同一动作时用）：
     regime == COPY_ALIGNED 且 |corr|>=0.5 -> COPY_ATTRACTOR
     其余                                 -> NO_CONTENT
```

**为什么这个顺序**：先证明"干预送到了"，再谈"干预有没有用"。
否则会把「探针坏了」误读成「机制无效」——NN 线的 pinn 作用面就因为这一点
**连续三版拿到假判负**（v113 / v114 / v115）。

## 5. Probe（探针）的写法

- **探针不许 import 训练脚本**：`cnn10_v*.py` 在模块级就 `CIFAR10(download=True)` + 建模型 +
  进训练循环，`importlib` 加载 = 触发整跑。
  ⇒ 正确做法：**逐字抽取被测函数到隔离命名空间执行**，再对源文件做静态核对。
- **探针要分节降级**：每节独立 `try`，任一段崩其余照常交付。
  否则一处 `math domain error` 会把全部读数打成 null。
- **探针要双写**：既写 `levels` 子键也写顶层平铺，避免读法不一致导致"恒读 0"（假判负）。
- **探针测的必须是生产那一项**：不要测一个"长得像"的量。
- **探针不许改原模型**：训练前跑的探针必须跑在 `copy.deepcopy` 上，
  并校验原模型 buffer 逐位未变（B 线实测：直接跑会改 **100+ 项 buffer**，
  其中 `phys2/3.update_count` 决定 `momentum` ⇒ 影响 `running_s/lam/nu` ⇒ **改训练轨迹**）。
- **还原到探针前状态**：`finally` 里无条件还原全局开关（如 `use_deterministic_algorithms`）。

## 6. 部署 / 执行两层自证（本仓库的工具链）

代码交付前跑三层检查，样板在 `tools/selfcheck/`：

| 层 | 脚本 | 检查什么 | v119 结果 |
|---|---|---|---|
| **生成器（幂等）** | `_gen_cnn10_v119.py` | 由父本 + 一组补丁**确定性地产出**子版本；重复运行必须 NO-OP | 幂等 NO-OP |
| **部署级（静态）** | `_deploy_check_cnn10_v119.py` | 版本同步、函数级 md5 零改动、新增函数计数、零 argparse、SystemExit 不增、preflight G1–G8 | **56/56** |
| **执行级（动态）** | `_cnn10_v119_exec_selftest.py` | 真 exec 抽取模块、判词各分支真跑、变异体咬红、负向对照 | **55/55** |
| **发车路径真跑** | `_v119_launch_path_check.py` | 把训练循环**截断后真跑一遍**，证明发车路径无代码缺陷 | **ALL GREEN** |

### 每条闸门都必须有负向对照

**没有负向对照的检查器不是检查器**。做法：把父本原文（或变异体）喂进去，
它必须**精确地报红**；若父本也能通过，说明这条闸门没有区分力 ⇒ 要么改，要么标为恒等项。

> 实例：部署级 C2 闸门（"父子同文"）对父本必然通过 ⇒ 无区分力 ⇒ 标为恒等项免对照并打印说明。

## 7. Provenance：sha1 分两级

| 级 | 判据 | 结论 |
|---|---|---|
| **字节级** | `sha1` 相同 | 同一份文件 |
| **数学级** | 训练数学指纹复现（如 A 线峰值 74.03@e791） | 同一代数学，可能不同字节文件 |

⇒ 发车前**必须**核对 sha1 与行数（见 [`07-reproducibility.md`](07-reproducibility.md)）。
历史教训：某版在训练机上跑的是**首版**（`eeb5dd3b…`）而非最终片（`d454…`），
跑了整轮才发现 ⇒ 那根轴白测一次。

---

## 8. 换行约定也是契约

B 线 / C 线 = **LF**；A 线 = **CRLF**。
统一换行会让 sha1 变化，从而破坏 MANIFEST 与全部历史读数的对应关系。
仓库根有 `.gitattributes` 固化这一点。
